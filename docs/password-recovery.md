# 密码修改与离线恢复

初始账号配置只用于创建用户，修改配置不会重置已有用户。已有短密码仍能登录；
新设置的密码至少 12 个字符，UTF-8 编码最多 72 字节。空格保留，不截断。

## 登录后修改

账号菜单 → 修改密码，输入原密码、新密码并确认。成功后当前浏览器回到登录页；
其他浏览器的该用户旧会话下一次请求返回 401。任务 ID、归属、运行任务和其他用户不变。
免登录模式不显示此入口，后端也拒绝改密。

`POST /api/auth/password` 接收 `currentPassword`、`newPassword`。
成功 204；参数/请求体超限 400；未登录 401；原密码错误/免登录模式/尝试上限 403；
并发密码冲突 409。按用户最多 15 分钟 5 次失败尝试，超限返回
`password_attempts_exceeded` 和 `Retry-After: 900`。请求体最多 4096 字节。
密码条件更新和会话撤销共用事务；登录签发会话必须再次匹配验证时的密码哈希。

## 维护者离线恢复

先自行停止对应主服务及全部工作进程，再从终端运行：

```powershell
tiler.exe admin reset-password --database C:/tiler/data/tiler.db --username admin
```

```bash
./tiler admin reset-password --database /opt/tiler/data/tiler.db --username admin
```

终端隐藏输入新密码并二次确认，不接受命令行明文密码或管道输入。
只处理已存在的数据库及用户，不初始化配置、不迁移数据库、不恢复或启动任务。
运行进程持有共享维护锁；恢复需要独占锁，冲突立即拒绝。
`.maintenance.lock` 是稳定的锁文件，不能在进程运行时手动删除。

更新前使用 SQLite `VACUUM INTO` 生成包括已提交 WAL 数据的一致性备份：
`原数据库路径.backup-UTC时间.db`。备份失败则密码不变；随后以单事务改密并撤销会话。
备份包含原认证信息和用户数据，应按数据库同等级保护并由维护者按保留策略管理。
工具不打印密码或哈希，不删除备份。升级前运行的旧版本没有维护锁支持，需先人工确认全部退出。

此文档是操作说明，本轮代码交付不执行生产密码恢复或生产服务停机。
